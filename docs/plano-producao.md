# Plano: Portal Bajeiros — do zero à produção

> **Nota (2026-08-22):** este plano (v1, site estático) segue válido como fundação e está executado no repo. A evolução p/ produto SaaS (auth, equipes, planos pagos, ODCS) está em `plano-producao-v2.md`, que estende este documento.

**Data:** 2026-08-22 · **Versão:** 1.1 (fundação executada)
**Stack alvo:** GitHub + GitHub Actions + AWS
**Natureza do app:** SPA 100% estática (Vite + React + react-three-fiber). Sem backend, sem banco, sem coleta de dados na fase 1. Todo o processamento (motor de regras B6) roda no browser.

Essa natureza estática define a arquitetura: **S3 privado + CloudFront** — superfície de ataque mínima, custo ~US$ 1–5/mês, escala automática. Sem servidores para gerenciar ou patchear.

## Fase 5 — Infraestrutura AWS (IaC)

**Ferramenta: Terraform** (estado da arte para esse escopo, comunidade grande). Diretório `infra/` no repo.

| #    | Passo            | Detalhe                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5.1  | Backend do state | Bucket S3 dedicado p/ tfstate + lockfile S3 nativo (`use_lockfile`) — criado via bootstrap manual único documentado.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 5.2  | Estrutura        | `infra/modules/static-site` + `infra/envs/staging` e `infra/envs/prod`. Mesma conta AWS, recursos separados por ambiente **Contas separadas deixam de ser opcionais antes da fase 2** (auth/dados de usuário) — pré-requisito registrado.                                                                                                                                                                                                                                                                                                                               |
| 5.3  | S3 do site       | Bucket **privado** (Block Public Access total), versionamento ON (rollback), encryption SSE-S3, acesso somente via CloudFront **OAC** (Origin Access Control).                                                                                                                                                                                                                                                                                                                                                                                                          |
| 5.4  | CloudFront       | Distribuição com: OAC → S3, HTTP→HTTPS redirect, TLS mínimo 1.2_2021, HTTP/2+3, compressão, `default_root_object=index.html`, custom error 403/404 → `/index.html` 200 (SPA fallback). **PriceClass_All** — é a única classe que inclui América do Sul (POP São Paulo); PriceClass_100/200 não cobrem BR.                                                                                                                                                                                                                                                               |
| 5.5  | Security headers | CloudFront Response Headers Policy: HSTS (max-age 2 anos, **sem `preload` no lançamento** — adicionar só após período estável), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` restritiva, `frame-ancestors 'none'`. **CSP entra como `Content-Security-Policy-Report-Only` no staging** (`default-src 'self'`; three.js exige `worker-src blob:`, `img-src 'self' data: blob:`; se decoders WASM entrarem, exigirá `'wasm-unsafe-eval'` em `script-src`); promove a enforce após validação sem violações. |
| 5.6  | ACM              | Certificado em **us-east-1** (exigência CloudFront), validação DNS, SANs: `bajeiros.com.br` + `www.bajeiros.com.br`.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 5.7  | Route53          | Hosted zone `bajeiros.com.br`, NS apontados no Registro.br. Alias A/AAAA → CloudFront. `www` → apex redirect (CloudFront function). Registros CAA (`amazon.com`).                                                                                                                                                                                                                                                                                                                                                                                                       |
| 5.8  | Staging          | `staging.bajeiros.com.br` — mesma stack, bucket/distro próprios. Header `X-Robots-Tag: noindex` no staging.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 5.9  | WAF              | **Adiado** (custo ~US$ 5+/mês; site estático sem backend tem pouco a proteger). Registrar como pendência consciente + AWS Shield Standard já é automático.                                                                                                                                                                                                                                                                                                                                                                                                              |

## Fase 6 — CD (deploy contínuo)

| #   | Passo                 | Detalhe                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 6.1 | OIDC GitHub→AWS       | IAM OIDC provider + 2 roles (`deploy-staging`, `deploy-prod`) com trust policy condicionada por **environment** (`repo:…:environment:staging` / `:environment:production`), casando com os environments do 3.6. **Zero access keys de longa duração.**                                                                                                                                                                                                                             |
| 6.2 | Permissões das roles  | Least privilege: `s3:PutObject/DeleteObject/ListBucket` no bucket do site + `cloudfront:CreateInvalidation` na distro. Nada mais.                                                                                                                                                                                                                                                                                                                                                  |
| 6.3 | Workflow `deploy.yml` | Merge em `main` → **build único** (artefato) → deploy **staging** (sync S3 + invalidation) → smoke test (curl 200 + título) → job `production` gated pelo environment (aprovação manual 1-clique) → **promove o mesmo artefato** (sem rebuild) → deploy prod → smoke test.                                                                                                                                                                                                         |
| 6.4 | Estratégia de sync    | Ordem: **assets hasheados primeiro, `index.html` por último** (nunca index novo apontando p/ asset ausente). Cache headers: `/assets/*` `cache-control: public,max-age=31536000,immutable`; `index.html` `no-cache`. Invalidation só de `/index.html` e `/`. Trade-off do `--delete`: remove assets antigos imediatamente — aceito porque index é `no-cache` (janela de risco ≈ 0 p/ SPA sem code-splitting agressivo); se virar problema, adotar janela de graça (delete adiado). |
| 6.5 | Terraform no CI       | Fase 1: `terraform plan` em PR (role read-only) + `apply` manual local documentado. Evolução: apply via pipeline com aprovação.                                                                                                                                                                                                                                                                                                                                                    |
| 6.6 | Rollback              | Runbook: reverter commit em `main` → pipeline redeploya; ou restaurar versão anterior do S3 (versionamento). Testar 1× antes do go-live.                                                                                                                                                                                                                                                                                                                                           |

## Riscos & decisões-chave (para revisão das personas)

1. **Repo privado vs público** — trade-off ferramentas de segurança grátis vs exposição do código.
2. **Terraform vs CDK vs SST** — escolhi Terraform; CDK integraria melhor com quem só vive AWS.
3. **Mesma conta AWS p/ staging+prod** — aceito na fase 1; contas separadas é best practice plena.
4. **WAF adiado** — aceitável p/ estático? Personas opinem.
5. **Apply do Terraform manual** — reduz blast radius de credencial CI onipotente; custo: fricção.
6. **CSP com three.js/R3F** — risco de quebrar WebGL/workers; exige validação em staging.
7. **Sem analytics/RUM** — cego p/ erros de usuário real; aceito p/ MVP?
8. **PriceClass** — All vs 200 vs 100 (latência BR × custo).
